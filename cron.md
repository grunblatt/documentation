There should be one main cron job, like this: */5 * * * * curl https://api.errands.nyc/cron. Only this cron job should be on the server. In the /cron directory, there are sub-cron jobs, and each sub-cron should be in a public URL. Before executing its function, a sub-cron should check a database table to determine the last time this specific cron ran. The main cron job should run as often as the minimum interval of any sub-cron route.

We don't care about permissions for the public URLs. The response from the cron routes should always be 200 OK with no other data, but log the results in the server's PM2. You can hit any sub-cron route whenever you want. If you want, you can add the option ?force to the URL, like <cronURL>/?force, to force the cron to run even if it has already run. There's no need to restart the cron on the server when updating the actual cron jobs.
